# SmartDNS для AI — проверка 16 октября 2026

## Добавленные варианты

| Вариант | DoH |
| --- | --- |
| DNS-AI (сохранён) | `https://dns.dns-ai.ru/dns-query` |
| GeoHide RU | `https://geohide.ru/dns-query` |
| GeoHide EU | `https://eu.geohide.ru/dns-query` |
| MALW | `https://dns.malw.link/dns-query` |
| MALW · CF | `https://5u35p8m9i7.cloudflare-gateway.com/dns-query` |
| Zapret DNS | `https://dns.zapret.moe/dns-query` |
| Comss.one | `https://dns.comss.one/dns-query` |

У зеркала MALW правильное окончание `.com`, не `.co`. Адрес сайта GeoHide
и его DoH отличаются наличием `/dns-query`. В каталог включены опубликованные
операторами адреса; начальные IPv4 сверены с их данными и публичным DNS.
Ответы системного FakeDNS из `198.18.0.0/15` не используются как bootstrap.

Первичные источники:

- [GeoHide: описание, региональные серверы и конфигурации](https://geohide.ru/)
- [GeoHide: опубликованные серверы](https://geohide.ru/static/metadata/servers.json)
- [MALW: основные адреса и зеркало Cloudflare](https://info.dns.malw.link/)
- [Zapret DNS: состояние и адрес подключения](https://dns.zapret.moe/)
- [Comss.one: официальные настройки](https://www.comss.ru/page.php?id=7315)

Xbox DNS исследован, но отдельный новый пресет не добавлен: на
[сайте оператора](https://xbox-dns.ru/) при проверке сообщалось о временной
недоступности. Существующая миграция старых ключей `comss`/`xbox` в DNS-AI
сохранена. Новый самостоятельный Comss имеет ключ `comss_smart`.

## Изменения приложения

- Провайдер для AI выбирается отдельно от общего DNS: настройки → разблокировка
  нейросетей → SmartDNS → выбор провайдера. Новые варианты доступны и в общем DNS.
- Исходный выбор DNS-AI сохранён; провайдер не переключается самовольно.
- Смена AI-провайдера применяется к активному SmartDNS-сеансу через перезагрузку
  конфигурации. В режиме AI/VPN смена не вызывает лишнее переподключение.
- AI/VPN и пользовательское правило «через VPN» получают обычный DNS вместо
  адресов SmartDNS-посредника, даже если общий DNS выбран из SmartDNS-каталога.
- Для всех используемых DoH-хостов добавлены bootstrap IPv4 и прямой HTTPS-маршрут.
- Удалена обязательная TLS-фрагментация AI: она стала отдельной опцией,
  выключенной по умолчанию. В сравнительных проверках включение фрагментации
  вызывало ошибки TLS/тайм-ауты, а без неё публичная страница Gemini открывалась.
- DoH идёт через обычный HTTPS независимо от опции фрагментации AI.
- AI-выход использует `ForceIPv4`: при ошибке выбранного DNS нет скрытого
  отката к системному резолверу. Стратегия описана в
  [документации Xray](https://xtls.github.io/config/transports/sockopt.html).
- Провайдер и настройка фрагментации сохраняются и входят в резервную копию.
- Полные импортированные JSON-профили по-прежнему используют собственные DNS
  и маршруты; эти настройки относятся к конфигурациям, генерируемым приложением.

## Что проверено по сети

Все семь DoH ответили по HTTPS/HTTP2 корректными DNS-пакетами на запросы
`gemini.google.com`, `chatgpt.com` и контрольного домена. Проверка сертификатов
включена. Исходные результаты: `build/ui-review/smart-dns-probes.json`.

Также проведены сравнения через отдельный экземпляр Android Xray 26.9.30
с SOCKS-входом на localhost, с фрагментацией и без неё. Этот тест не запускает
VPN и не меняет системные настройки сети. Строгий вариант без фрагментации
использует выбранный DoH, `disableFallbackIfMatch` и `ForceIPv4`.

Публичная страница Gemini вернула HTTP 200 через все семь вариантов
без фрагментации; для MALW · CF встречались повторные запросы DNS
и увеличенное время ожидания. ChatGPT вернул HTTP 403 с защитной страницей:
это подтверждает соединение и проверку TLS, но не работу чата в аккаунте.

Результаты из текущей сети не гарантируют доступ на каждом операторе РФ.
Вход, отправка сообщений, подписки и региональные условия аккаунтов не тестировались.
Отсутствие `location=unsupported` в HTML само по себе не считается полноценной
проверкой регионального доступа. Сравнение с фрагментацией подтверждает
несовместимость в проверенной цепочке, а не универсальный запрет фрагментации.

## Проверки сборки и интерфейса

Модульные тесты проверяют выбор каждого провайдера, bootstrap, разделение DNS
для AI/VPN, приоритет пользовательских маршрутов, отсутствие системного отката
и независимость DoH от фрагментации. Отдельно проверяются конфигурации настоящим
Android-ядром Xray. Итог: 122 теста пройдены, без ошибок и пропусков; настоящее
ядро проверило 36 конфигураций. Обычная debug-сборка с исходным applicationId
также успешно собрана.

В отдельной тестовой копии проверены меню со всеми семью вариантами, выбор
MALW · CF, сохранение после перезапуска, переключение SmartDNS/VPN без потери
провайдера и включение/выключение фрагментации. Снимки находятся в
`build/ui-review/smartdns-settings.png`, `smartdns-picker.png`, `smartdns-selected.png`.

На эмуляторе основное приложение имеет другую подпись. Его данные не удалялись;
для проверки интерфейса использован отдельный пакет `com.danieldk.splatevpn.smartdnsqa`.
После проверки тестовая копия удалена. Для обновления основной установки
нужен APK с тем же ключом подписи; debug APK с другим ключом её не заменяет.
